# NAND ラボ

NAND だけを与えられた状態から、論理回路を自分の手で組み上げていくサンドボックス。
ブラウザだけで動く（依存ゼロ・サーバ不要・通信なし）。

作った回路は**チップとして登録**でき、次の回路の部品として置ける。
NOT を作り、それで AND を作り、それで加算器を作り……と階層を積み上げていくと、
最後は「記憶する回路」まで届く。

```
NAND ─→ NOT ─→ AND ─→ OR ─→ XOR ─→ 半加算器 ─→ 全加算器 ─→ 4ビット加算器
                        └─→ セレクタ            └─→ 2ビット乗算器
                              SR ラッチ ─→ D ラッチ ─→（ここから先は「ここから先」の節へ）
```

---

## 起動

`起動.vbs` をダブルクリック（既定のブラウザで `index.html` が開く）。

**初めて開くと、空の盤面ではなく NAND 1個の回路が置いてある。**
A と B をクリックしてみると、両方 1 のときだけ Y が消える。それが NAND で、
このアプリでできることは全部これの積み重ねでしかない。消したければ「作業台を消す」。
`index.html` を直接開いてもよい。ビルドもインストールも要らない。

URL パラメータ:

| | |
|---|---|
| `?fresh=1` | 保存を無視して空から始める |
| `?quest=xor` | 最初から選んでおく課題（id は下の表） |

## 最初の5分 ― NOT を作る

1. 左のパレットで **入力** をクリック → 盤面をクリック。スイッチ「A」が置かれる。
2. 同じように **NAND** と **出力**（「Y」）を置く。
3. 「A」の**右側の丸**から、NAND の**左側の丸（上）**へドラッグ。線が繋がる。
4. もう一度「A」の右の丸から、NAND の**左の丸（下）**へドラッグ。NAND の両方の入力に同じものを入れる。
5. NAND の右の丸から「Y」の左の丸へドラッグ。
6. 「A」をクリックして切り替えると、「Y」が逆に光る。**これが NOT**。
7. 右のパネルで課題「NOT」を選び、**採点する**。
8. 上の **チップにする** で `NOT` という名前を付けると、パレットに `NOT` が並ぶ。次から部品として置ける。

あとはこの繰り返し。

### 上のバー

- **止める / 動かす** ― 時間を凍らせる。止めている間はスイッチを動かしても値が広がらない。
  `Space` で1歩ずつ進めると、信号が波のように伝わっていく様子と、発振がどこで暴れているかが見える。
- **リセット** ― 全部を X（未定）に戻す。ラッチの記憶も消える。
- **真理値表** ― 今の回路の入力を全通り試して表にする。
- **論理式** ― 回路を式として読む。下の節を参照。
- **道のり** ― 31問の課題を、依存の木として見る（下の「道のり」の節）。
- **小さくする** ― 今の回路から、素子を減らせる所を探して指さす（下の節）。
- **整える** ― 配置を並べ直す（下の「整える」の節）。
- **チップにする** ― 今の作業台の回路まるごとを名前つきの部品にする。
- **上書き保存** ― チップを作業台に取り出しているときだけ出る。`Ctrl+S`。
  名前を打ち直さずにそのチップの定義を入れ替える（打ち間違えて別のチップが増えるのを防ぐ）。
- **作業台を消す** ― 回路を空に。チップの定義は残る。
- **書き出し / 読み込み** ― JSON。人に渡すときはこれ。

## 課題

右のパネル。**31問・6つの章**。組み合わせ回路は真理値表を総当りで、順序回路は入力を順に与えて採点する。
上のバーの **道のり** で、どの課題が何の上に建っているかを図で見られる。

課題には「これができると何ができるか」を付けてある（`why`）。
XOR が「1桁の足し算の答えそのもの」、D フリップフロップが「CPU の ◯GHz はこの拍の速さ」、

第2章の 11〜13 は誤り訂正の3部作。パリティで「化けに気づく」、ハミング符号で
「どこが化けたか分かる」、訂正器で「直す」まで行く。第3部「メモリの物理」の
ECC の実体で、2ビット化けると別の場所を"直して"しまう（距離3の限界）ことも
真理値表ごと採点される。

第6章は原始部品を NOR に取り替える（パレットの NOR）。**素子は混ぜない** ― 第6章は NOR 素子だけ、第1〜5章は NAND 素子だけで採点する。混ぜてよいことにすると、第1章の「NOR」が NOR 素子1個で済み、第6章は NAND の世界で作ったチップを持ち込むだけで済んでしまう。NAND 4個の XOR と同じ配線を NOR でやると XNOR になる（全部の線の 0 と 1 を入れ替えて見ると NAND は NOR に、XOR は XNOR に写る ― 双対）。NOR の SR ラッチは S・R が「1 で効く」（NAND のラッチは「0 で効く」）。

「お手本の NAND 数」は `tests/quest.js` が実際に組んだ解答の実測値。
少なければ偉いという話ではない（全加算器は最小で 9 個にできるが、
半加算器チップを2つ使う素直な組み方だと 13 個になる）。
NOT の 1 個から ALU の 124 個まで、**同じ NAND だけで 124 倍に育つ**のがこの表の見どころ。

**採点は端子の名前で照合する。** 課題が `A`・`B` → `Y` を求めているなら、
入力部品の名前も `A`・`B`、出力部品の名前も `Y` でなければならない。
右のパネルの端子タグは、その名前が今の回路にあると緑になる。

## 仕組み

依存の向きは上から下への一方通行。上の層は下の層を知らない。

```
netlist.js   回路のデータ構造（部品・配線・端子）。純粋なデータ操作だけ
   ↓
lib.js       チップの登録と、階層を潰して平らにする展開
   ↓
sim.js       3値・単位遅延・イベント駆動のシミュレータ
   ↓
truth.js     真理値表の抽出、ループの検出、期待表との突き合わせ
   ↓
quest.js     課題の定義と採点
expr.js      回路を論理式として読み、整理する
   ↓
store.js     localStorage への保存と JSON 入出力
layout.js    配置の自動整列（部品の寸法は ui.js から貰う）
mos.js       NAND の中身（CMOS のトランジスタ4個）の状態
slim.js      素子を減らせる所を探す
answer.js    31問のお手本回路（画面と検査で同じものを使う）
   ↓
ui.js        canvas への描画と、マウス・キーボードの操作
   ↓
main.js      起動
```

`ui.js` 以外はブラウザに一切触らない。だから `tests/` は全部 Node だけで走る。

## NAND の中身 ― 物理層

盤面の **NAND をダブルクリック**すると、その NAND の中身がトランジスタで出る。
**値はその素子に今来ているもの**なので、盤面のスイッチを切り替えると中のスイッチが開け閉めされる。
窓を小さくしてあるのは、盤面を触りながら見るため。

```
            電源 1
      ┌───────┴───────┐
   ─┤ p(A)         ─┤ p(B)      ← p 型: ゲートが 0 のとき通じる（並列）
      └───────┬───────┘
              ├──────── Y
           ─┤ n(A)              ← n 型: ゲートが 1 のとき通じる（直列）
              │
           ─┤ n(B)
              │
            地面 0
```

- **A も B も 1** → 下の n が2つとも通じ、Y は地面まで一本道 ― 引き下げられて **0**
- **どちらかが 0** → 上の p が通じ、Y は電源まで届いて **1**

これがそのまま NAND の表になる。**上と下が同時に通じることは無い**ので、電源から地面へ
電流が流れ続けない ― CMOS が発熱しない理由がこの形にある。

そして **AND を作るには、この後ろに NOT（さらに2個）を足して6個要る**。
NAND のほうが部品が少なく、しかも速い。**原始部品を NAND にした物理的な理由がここにある。**

### 絵で守っている約束

色の役割を2つに分けてある。混ぜると読めなくなる。

| | |
|---|---|
| **線の色** | その節点の**電位**（1 は緑 / 0 は青 / 未定は灰）。盤面の信号の色と同じ約束 |
| **縦棒の色** | そのトランジスタが**通じているか**（黄＝通じている / 沈んだ色＝切れている） |

- **繋がっている線は1本の太線**で、同じ色で描く。「どこが同じ電位か」が形で分かるように。
- **入力は左右の端から入り、ゲートにだけ繋がる。**通り道には触れていない ― それが MOS。
  ゲートの板と通り道のあいだに隙間を空けてあるのはそのため。
- p 型のゲートに付いている丸は「0 で効く」の印。
- n どうしの間の節点は、下が切れているときは **宙に浮いている**（0 とは書かない）。

3値（0/1/X）はここでも崩さない。ゲートに来ている値が X なら、そのスイッチは
「通じるとも切れるとも言えない」。ただし**片方が 0 なら、もう片方が X でも上は通じている**ので、
そのときは Y が 1 に決まる ― 3値の要になっている性質が、物理の絵の上でもそのまま見える。

`tests/run.js` は、この中身が出す答えと**シミュレータの NAND が全9通りで一致すること**を
確かめている。ここがずれると、見せている物理が嘘になる。

### 電圧で見る ― 0 と 1 の下にある連続量

中身の窓の **電圧で見る** を押すと、同じ NAND を「入力 A の電圧 → 出力の電圧」の坂で見せる（`analog.js`）。
0 と 1 は、この坂をしきい値で切っただけのもの。

- 坂の傾きが −1 になる2点の外側では、入力の汚れが出力で**小さく**なる ― 押し戻される。
  だから何千段積んでも信号が濁らない。これが「0 と 1 だけで考えてよい」理由そのもの
- 坂の途中（灰色の帯）が「どちらとも言えない」電圧で、**3値の X はここに居る**
- 盤面の入力を切り替えると点が動く。A が X のときは点を打たない（0 で埋めるとこの絵は嘘になる）
- もう片方の入力 B を 0 にすると坂は消えて出力は 1 に張り付き、B を弱くすると坂は右へ動く（下の n が直列だから）

モデルは教科書の一番素朴な二乗則（level 1）。n と p は同じ強さ、電源 3.3V。しきい値は既定 0.7V だが、
**[SemiLab](../SemiLab/) 第5章「NAND の中身へ」の採点を通すと、そこで作った nMOS の Vth がここへ渡り**、
坂がその素子で描かれる（画面に「SemiLab 第5章で作った nMOS」と出る。渡るのは Vth だけ ―
このモデルは n と p の強さの比しか効かず、比は 1 に固定しているので Cox は坂の形を変えない）。
受け渡しは `localStorage`（キー `SemiLab.nmos`）。同じブラウザで開くことと、`file://` の
localStorage をページ間で共有するブラウザ（Chromium 系は共有する）であることが条件で、
読めないときは黙って既定値 0.7V に戻る（画面に「既定値」と出るので区別できる）。
実物の細かい振る舞いは出ないが、「坂ができる」「利得が 1 を超える」「上下の釣り合いで出力が決まる」という肝は同じ。
`tests/run.js` は、電圧で解いた答えを 0/1 に読み戻すと**スイッチの絵と全4通りで一致すること**、
雑音余裕が電源の 1/4 以上あること、坂の利得が 1 を超えることを見ている。
参考書側の説明は [論理回路の基礎](../第3部_論理回路.html) の 01 章。

## 小さくする ― 素子を減らす

上のバーの **小さくする**。一般論ではなく、**今の回路を指さして**言う。

見つけるのは、機械が確かめられることだけ:

| | |
|---|---|
| 同じものを2つ作っている | 入力が同じ素子は、出力も必ず同じ。1個にまとめて枝分かれさせれば足りる |
| どこにも届いていない | 出力部品まで辿り着かない素子。消しても動きは変わらない |
| 打ち消し合う NOT | ひっくり返して、また戻している |

**手がかりをクリックすると、その素子が盤面で選ばれる。**読んで終わりにせず、直す所まで連れて行く。

「ド・モルガンでこう変形できる」の類は出さない。機械が式を睨んで出す助言は、
当たっていても人が納得できず、外れていると回路を壊す。考え方のほうは同じ窓の下半分に
文章で置いて、指さす助言とはっきり分けてある。

**順序回路の落とし穴**: 入力が同じでも、記憶を持つチップ（ラッチ・フリップフロップ）は
まとめてはいけない。中身の状態がたまたま違うことがあり、まとめると別の回路になる。
だから「輪のあるチップ」は対象から外している。NAND そのものは記憶を持たないので安全。

## お手本を見る

課題のパネルの **お手本を見る**。その課題を実際に組んだ回路が、整えた状態で出る。
**見るだけで、作業台には触らない。**

お手本の実体は `src/answer.js` にあり、**画面と検査（`tests/quest.js`）が同じものを使う。**
別々に持つと、検査を通っているお手本と人が見るお手本が食い違う。
`tests/quest.js` は31問すべてについて、このお手本が本当に採点を通ることと、
NAND 数が課題の `goal` と一致することを毎回確かめている。

同じ形にする必要はない。**通ればどう組んでもよい**（お手本の全加算器は 13 個だが、最小は 9 個）。

## 数として読む ― 束

同じ語幹＋数字の入力・出力（`A0`〜`A3` など）が2本以上そろうと、**束**として扱い、
盤面の右上に二進の並びと十進の値を出す。`V` で消せる。

```
A   0111    7
B   0101    5
S   1100   12
```

4ビット加算器を組んで A に 7、B に 5 を入れると、**S に 12 と出る**。
これが無いと、光の並びを目で二進に直す作業がずっと必要で、
自分が足し算機を作ったという実感がどこにも来ない。カウンタにクロックを繋ぐと、
この数字が 0 から 15 まで自分で回りはじめる。

- **添字 0 が最下位**（課題の端子の付け方と同じ）。
- **1ビットでも X なら数にしない**（`―` と出る）。0 で埋めると、繋ぎ忘れやリセット前が
  「たまたま 0」に見えてしまう。
- 1本しかない名前は束にしない。

## 配線に名前を付ける

配線をクリックして選び、`F2`。線の一番長い横棒の真ん中に名前が出る。
**回路の意味は何も変わらない ― 読む人（数日後の自分）のための札。**

名前を付けたくなる線は、たいてい「あとで自分が探す線」（桁上がり・書き込み許可・クロック）。
端子と違って重複を禁じていないのは、同じ信号から分かれた枝に同じ名前を付けたいから。
空にすれば消える。

## 道のり ― 積み上がっているのを見る

上のバーの **道のり**。31問を章ごとに6段で並べ、「先に作っておくと楽な課題」を線で結んだ図が出る。

- **緑** ＝ クリア済み　/　**青** ＝ 材料が揃っていて今すぐ作れる　/　**沈んだ箱** ＝ まだ材料が無い
- 箱の中の数字は**お手本の NAND 数**。上の段へ行くほど大きくなる。NOT の 1 個から ALU の 124 個まで、
  増えているのは同じ NAND の数だけ。
- 箱をクリックするとその課題を選ぶ。

図の上に3つの数を出している。**積み上がっている感じ**は、この3つで測れるようにした。

| | |
|---|---|
| クリア数 | 31問のうちいくつ通ったか |
| 全部ばらすと NAND ○個 | 登録済みチップを全部 NAND まで展開したときの合計。使い回しは使った回数だけ数える |
| 一番深いのは ○（NOT から数えて ○ 段目） | チップの階層の深さ。NAND だけでできたチップが 1 段目、それを使うチップが 2 段目 |

深さは `lib.depth()`。**素子数とは別のものを測っている。**
素子数は「どれだけ大きいか」、深さは「何回積み上げたか」。
4ビット加算器は 52 素子だが深さは 4（NOT → AND/XOR → 半加算器 → 全加算器 → 加算器）。
パレットのチップにも素子数が出ていて、チップにした瞬間にも
「ばらすと NAND ○個、NOT から数えて ○ 段目」と表示する。

## 整える ― 配置の自動整列

上のバーの **整える**（`L`）。手で並べた回路は、繋ぎ足していくうちに線が交差して
読めなくなる。押すと「信号が左から右へ流れる」形に並べ直す。**`Ctrl+Z` で元に戻せる。**

- **部品を2つ以上選んでいれば、その中だけ**を整える。選んでいなければ盤面ぜんぶ。
- 整えたものは元あった場所の左上に置き直す。押すたびに画面の外へ飛んでいかない。
- 繋がっていない別々の回路は、混ぜずに上下に分けて並べる。
- **回路の意味は何も変わらない。** 位置を動かすだけなので、動いている回路の
  ラッチが覚えている値も消えない（シミュレータを作り直さない）。
- **配線が部品を突き抜けない。** 下の「通し道」を参照。

やっていることは層状グラフ描画の定石そのままで、3段階:

1. **段を決める** ― 上流から数えて何段目か（最長路）。これがそのまま列になる。
   出力は一番右の列に揃え、定数とクロックは使われる直前まで右へ寄せる。
2. **並びを決める** ― 同じ列の中の上下を、隣の列での位置の中央値の順に並べ替える。
   左右に4往復。交差を最小にするのは NP 困難なので、十分に減らす方に倒す。
3. **位置を決める** ― 配線が真横になる y へ寄せ、重なった分だけ押し戻す。
   入力側に合わせる回と出力側に合わせる回を交互にやる（片方だけだと上流しか揃わない）。

### 通し道 ― 配線が部品を突き抜けないようにする

列を2つ以上またぐ線は、途中の列を素通りする。何もしないと、その列に並んだ部品の上を
横切って、線と箱が重なって読めなくなる。手で組んだ回路を整えると、これが一番効く。

対策は2つ組み合わせてある。

1. **通し道**（`layout.js`）― またぐ列ごとに「大きさゼロの部品」を置き、線をそこで折り返す。
   この点は場所の取り合いに普通に参加するので、通り道ぶんの隙間が空く。
   同じ出力端子から出た線は同じ信号なので、道も1本にまとめる。
   **通し道は押し下げられない** ― 押し下げると線が実際に通る高さとずれて、
   空けたはずの隙間の外を線が通る。代わりに上に居る部品を持ち上げる。
2. **通り道を配線に覚えさせる**（`wire.pts`）― 整えたときに決めた折れ線を配線が持つ。
   端子の位置から毎回計算し直す描き方だと、道が他の部品に押しのけられた場合に
   隙間の外を通ってしまう。

覚えた道は、**部品を動かした瞬間に端子と合わなくなるので自動的に捨てられ**、
素直な折れ線に戻る。「古いかどうか」を別の印で持たないのがミソで、
印を消し忘れると部品と繋がっていない線が残る。

覚えた道が無い線（隣の列どうし）は、**行き先の直前で曲がる**。真ん中で曲がると、
その縦棒が列の真ん中に立って部品を突き抜けるため。入る端子ごとに折れる位置を少しずらして、
同じ部品に入る線どうしが重ならないようにしてある。

`tests/layout.js` は「部品を突き抜けている配線の数」を実際に描かれる折れ線で数えていて、
整えたあとは 0 になる。

**寸法は `ui.js` から貰う。** 部品の大きさと端子の位置は画面の持ち物なので、
`layout.js` の中で同じ計算をもう一度書くと、片方を直したときにもう片方がずれて
「整えたのに線が斜め」になる。`NL.ui.geom` をそのまま渡している。

**真横にならない線もある。** 端子の間隔は 20 なのに部品の高さは 40 以上あるので、
1つの NAND の2本の入力をそれぞれ別の入力スイッチから引くと、
スイッチ2つを 20 の間隔には置けない。どちらかは必ず斜めになる。

**フィードバックは直せない。** ラッチは輪になっているので、どう並べても
右から左へ戻る線が残る。後ろ向きの線は段を決めるときだけ外し、
並びの計算には使っている（戻り先の近くに置きたいので）。

## 論理式で過程を見る

上のバーの **論理式**。回路を式として読み、2段で見せる。

**まとめ** ― 各出力の、最後まで整理した式。

```
S = A ⊕ B
Y = A · B
```

**過程** ― NAND を上流から順に1行ずつ。左が「回路のとおり」、右が「整理すると」。
式が育っていく様子がそのまま出る。

```
信号   回路のとおり      整理すると
s1     ¬(A · B)          ¬(A · B)
s2     ¬(A · s1)         ¬(A · s1)
s3     ¬(B · s1)         ¬(B · s1)
s4     ¬(s2 · s3)        A ⊕ B
s5     ¬(s1 · s1)        A · B
```

2箇所以上から使われる信号（上の `s1`）は、以降の式でその名前のまま出る。
全部を展開すると 4ビット加算器あたりで式が数千文字になって読めなくなるため。

### 整理に使っている書き換え

```
¬¬x            → x
x·x            → x                （同じものは1つにまとめる）
x·¬x           → 0,  x+¬x → 1
¬(¬a · ¬b)     → a + b            （ド・モルガン）
a·t + b·t      → (a+b)·t          （共通因子でくくる）
¬(a·b) · (a+b) → a ⊕ b
a·¬b + ¬a·b    → a ⊕ b
```

この程度の規則しか無いが、NAND で組んだ NOT・AND・OR・XOR・セレクタ・加算器は
これで人が書くのと同じ形まで戻る。XOR は「くくる」を先にやらないと気づけない
（`¬(a·b)·a + ¬(a·b)·b` → `¬(a·b)·(a+b)` → `a ⊕ b`）。

### ループがあると式にならない

順序回路の出力は「今の入力」だけでは決まらない。SR ラッチの Q は S と R の式では
書けない（同じ入力に対して答えが2つある）。無理に何かを出すより、
順序回路であることをはっきり言う。動きを見たいときは「止める」＋「1歩」で追う。

繋ぎ忘れた入力は `X` のまま式に出る（`Y = ¬(A · X)`）。0 で埋めたことにしない。

## 設計判断とその理由

### 原始部品は NAND だけ

AND も OR も XOR も、最初から用意されていない。それを作るのがこのアプリだから。
例外は「値を外から入れる/外へ出す」ための端子と、定数とクロックだけ。
これらは論理素子ではなく、回路と外界の境目。

第6章だけは原始部品を NOR に取り替える（NOR も万能ゲート）。そのときも論理素子は1種類だけ ― NAND と NOR を混ぜた回路は、どちらの章でも採点で断る。NOR をダブルクリックしても中身の絵は出ない（CMOS の NOR は pMOS 2個が直列・nMOS 2個が並列で、NAND と上下が逆。絵は NAND のぶんだけ用意してある）。

### 信号は 3値（0 / 1 / X）

`X` は「まだ決まっていない」。**これが無いと嘘の回路が動いてしまう。**

0/1 だけだと、電源を入れた瞬間のフリップフロップが 0 から始まる。実物はどちらに
転ぶか分からない。X があると「リセットを入れるまで中身は読めない」という本当の挙動になり、
リセット線を忘れた回路はちゃんと動かない。繋ぎ忘れた入力も X になるので、
「繋ぎ忘れているのに偶然動いている」が起きない。

NAND の3値表で大事なのは、**片方が 0 なら、もう片方が未定でも出力は 1 で確定する**こと:

|        | b=0 | b=1 | b=X |
|--------|-----|-----|-----|
| **a=0**|  1  |  1  |  1  |
| **a=1**|  1  |  0  |  X  |
| **a=X**|  1  |  X  |  X  |

### 収束反復ではなく、単位遅延のイベント駆動

「出力が変わらなくなるまで全ゲートを計算し直す」方式は、**フィードバックのある回路
＝ラッチで原理的に破綻する**。SR ラッチは同じ入力に対して答えが2つある（Q=0 でも Q=1 でも
辻褄が合う）ので、不動点が一意に決まらない。

全ゲートに遅延 1 を与えて時間を1歩ずつ進めれば、ラッチは自然に「前の状態を保つ」ようになり、
禁止入力から抜けたときの発振も、発振としてそのまま観測できる。

1歩の中では**評価と反映を分ける**。1つずつ書き戻すと、評価する順番によって答えが変わり、
同じ回路が実行のたびに違う挙動になる。

### チップは展開してから回す

シミュレータは階層を知らない。回す前にチップを再帰的に潰して、
`nand` と `src`（値の源）と `buf`（中継）だけの平らな配列にする。

チップの境界は `buf` として残す。境界のネットを消して両側を直結する方が速いが、
そうすると「このチップのこの端子に今なにが来ているか」を画面に出せなくなる。
遅延が1段増えるだけなので残している。

ゲート i の出力ネットの番号は i と同じ。ネットとゲートを別々に採番すると、
対応表を持ち歩くことになる。

### 端子は必ず 10px 格子の上に載せる

端子の y が半端な値だと、部品の高さが違うだけで配線が斜めになり、
どう動かしても直線にできない（`46/3 = 15.33…` のような座標が出るため）。
そこで寸法を次の規則で決めている:

- 端子の間隔 `PITCH` は格子の偶数倍（20）
- 部品の高さは必ず 20 の倍数 → 中心 `h/2` は 10 の倍数
- 端子は中心から上下に対称 → ずれは `(端子数-1)×10` で 10 の倍数

よって端子の y は常に 10 の倍数。部品は格子に吸い付くので、
上下に動かせば任意の2端子をぴったり揃えられる。

### 端子の並び順は「名前の自然順」

座標順にすると、部品をちょっと動かしただけで端子の順番が入れ替わり、
そのチップを使っている側の配線が黙って繋ぎ変わる。名前なら動かない。

自然順なので `A1 < A2 < A10`。辞書順だと `A10` が `A2` より前に来て、
4ビット加算器の端子の並びが人間の直感とずれる。

### チップは「登録した時点のコピー」、参照は「名前」

作業台をいじるたびに登録済みチップの中身が変わると、何を測っているのか分からなくなる。
だから定義は登録時のスナップショット。

一方、盤面に置いたチップは**名前で**定義を引く。だから
**同じ名前で登録し直すと、そのチップを使っている回路すべてが新しい中身に入れ替わる**。
これは意図した挙動（バグを直したら全部に反映されてほしい）。
端子の数や名前が変わったときは、行き先を失った配線は展開時に黙って捨てられ、
`netlist.validate` が「存在しない端子を指しています」と指摘する。

## 踏みやすい落とし穴

- **チップの端子の順番は、作った順ではなく名前順。**
  SR ラッチを `S`・`R` の順で作っても、チップの入力は `R`・`S` の順に並ぶ。
  配列の添字で繋ぐと取り違える。`tests/quest.js` はこれを一度踏んで、
  名前で指定する `chipn()` を足した。

- **NAND を輪にしただけでは発振しない。** 全部が X のままでも3値の理屈は辻褄が合う
  （`NAND(X, X) = X`）。リング発振器を作るなら、既知の値を注ぐ口（起動用の入力）が要る。
  実物のリング発振器に必ず起動用のゲートが付いているのと同じ理由。

- **入力スイッチの初期値は 0。** SR ラッチのように「0 で効く」負論理の回路を組むと、
  電源投入直後がいきなり禁止入力になっている。課題の採点は `reset()` のあとに
  `settle()` せず、最初の手順の入力を与えてから初めて時間を進めることで
  これを避けている（settle してしまうと手順1で発振する）。

- **数の表示は 0 で埋めない。** 束に X が1つでもあれば `―` と出す。0 で埋めると、
  繋ぎ忘れやリセット前の状態が「たまたま 0」に見えて、3値にした意味が消える。

- **名前の変更はダブルクリックではなく `F2`。** 入力スイッチはクリックのたびに 0/1 が
  切り替わるので、かちゃかちゃ切り替えているだけで名前の窓が開いてしまった。
  ダブルクリックはチップの中を覗く専用。入力・出力をダブルクリックしたときは
  「F2 で変えられる」とだけ言う（探しに行く場所がそこなので）。

- **時間を止めているとき、スイッチを動かしても値は広がらない。** 仕様。
  `Space` で1歩ずつ進める。これを知らないと「壊れた」に見える。

- **`*.vbs` は UTF-16LE(BOM) で保存すること。** UTF-8 だと日本語の文字列リテラルが
  壊れて起動しない。先頭バイトが `FF FE` か確認する。`.gitattributes` で `binary` 指定済み。

## 検査

```
node tests/all.js       全部（725件）
node tests/run.js       エンジンの単体検査（NAND の中身・減らす手がかりを含む）
node tests/expr.js      論理式が人の書く形まで戻ることの確認
node tests/quest.js     全課題のお手本解答を実際に組んで採点が通ることの確認

node tests/ui.js        画面の通し検査（ブラウザ不要）

```

全部 Node だけで走る。ブラウザは要らない。

- `tests/expr.js` ― NAND を積んだだけの回路が `A ⊕ B` や `A · ¬S + B · S` まで戻ること。
  ここが通らないと「論理式」ボタンは `¬(¬(A·B)·¬(A·B))` のような読めないものを出す。
- `tests/quest.js` ― NOT から 4ビット ALU まで、31問ぜんぶのお手本（`src/answer.js`）を
  実際に下から積み上げて採点にかける。**画面の「お手本を見る」が出すのと同じもの**なので、
  ここが通ることは「人が見るお手本が本当に正しい」ことでもある。
  D フリップフロップ・レジスタ・カウンタは、チップの境界をまたいで出力を自分の入力へ
  戻す構成なので、ここが通ることは「階層のあるフィードバックが本当に動く」ことの証明でもある。
  課題の期待表そのものの検算でもあり、チップ機構（階層・展開・境界をまたぐフィードバック）の
  総合試験でもある。わざと間違えた回路がちゃんと落ちることも見ている。
- `tests/layout.js` ― 散らかして置いた回路を整えて、左から右に並ぶこと・重ならないこと・
  交差が解けること・**配線が部品を突き抜けないこと**・端子が格子に載ること。**寸法は `NL.ui.geom` から貰って測る**
  （ここで寸法を別に書くと、検査は通るのに画面ではずれる）。
- `tests/ui.js` ― `tests/dom.js` の薄いニセ DOM の上で `ui.js` を動かし、
  人がやる手順（置く→繋ぐ→切り替える→採点→チップ化→中を覗く）をそのまま踏む。
  座標の計算には**画面の当たり判定と同じ関数**（`NL.ui.geom`）を使っている。
  別実装にすると検査が嘘になる。

**消さないでほしい検査:**

- `tests/run.js` の「電源投入直後は未定。0 から始まったりしない」
  ― X を消したくなったときの歯止め。
- `tests/quest.js` の「わざと間違えた回路は落ちる」
  ― 採点が素通りするようになったことに気づけなくなる。
- `tests/ui.js` の「盤面をちゃんと描いている（真っ白ではない）」
  ― 描画命令の数を数えている。例外を握り潰したときに気づける。

## ここから先 ― CPU までの道順

課題は **4ビット ALU まで**（第5章）。レジスタ・カウンタ・ALU が揃った時点で、
CPU に足りないものは「メモリ」と「順番に指示を出す仕掛け」の2つだけになる。
ここから先は課題になっていないので自由制作。

1. **プログラムカウンタ**（4ビットカウンタに「好きな値を入れる」口を足す。分岐がこれでできる）
2. **命令デコーダ**（命令の上位ビットを 2→4 デコーダに通し、レジスタの W や ALU の S を叩く）
3. **メモリ**（ここで詰まる。下記）

ここまでは手で配線できる範囲。**その先はメモリで詰まる。**
16語×4ビットの RAM を NAND で組むと 600素子を超え、手で配線するのは現実的でない。

そこで、パレットに **RAM16（16語×1bit）を実装部品として足してある**。
「原始部品は NAND だけ」の唯一の例外で、画面でも正直にそう名乗る:

- パレットの説明・盤面の見た目（琥珀色の箱）・ステータス行、全部に「実装部品」と書いてある
- **課題の採点では使えない**（置いてあるだけで断られる。課題は NAND から組むのが主題）
- 「論理式」も断り、「小さくする」は RAM16 入りのチップをまとめの対象から外す

端子は `A0..A3`（番地）, `D`（書く値）, `W`（書き込み許可）, `C`（クロック）→ `Q`（読み出し）。
`C` の立ち上がりで `W=1` なら `cells[番地] = D`、読み出しは組み合わせ（遅延1歩）。
電源投入直後は全セル X（書くまで読めない ― フリップフロップと同じ約束）。
X の扱いも NAND の3値表と同じ発想で嘘をつかない:
立ち上がりや `W` に X が絡んだら「書いたかもしれない」セルを X にし、
番地に X があれば「どこに書いたか分からない」ので巻き添えのセルも X になる。
盤面の RAM16 をダブルクリックすると16セルの中身が見える。検査は `tests/ram.js`。

これで 1bit 幅の RAM が4つあれば 16語×4bit。プログラムカウンタ・命令デコーダと
合わせると、手で配線できる範囲で CPU の骨格まで届く。
（足した場所はコードの4箇所: `netlist.js` の `PRIM` / `lib.js` の `expand` /
`sim.js` の `evalRam` / `ui.js` の `GEO`・`drawPart`。ROM を足したくなったら同じ道順で）

**NAND 純血は課題の中では保つ方針。** RAM16 は自由制作のための例外で、
だからこそ採点が拒み、画面が「実装部品」と名乗り続ける。ここを崩すと本体が無くなる。

### 下へ ― NAND の中身の、さらに中身

中身の窓の「電圧で見る」（`src/analog.js`）は、[SemiLab](../SemiLab/) 第5章「NAND の中身へ」の
採点を通すと、**そこで作った nMOS の Vth を受け取って坂を描く**ようになった（上の「電圧で見る」の節）。
残っているのは電源 3.3V の決め打ちと、p を n の鏡像とする単純化。SemiLab 側に pMOS の課題ができたら、
n と p の強さの比もここへ渡せる。
学びの地図（[../index.html](../index.html)）では第3部にあたり、参考書は [論理回路の基礎](../第3部_論理回路.html)。
