# NAND ラボ

NAND だけを与えられた状態から、論理回路を自分の手で組み上げていくサンドボックス。
ブラウザだけで動く（依存ゼロ・サーバ不要・通信なし）。

作った回路は**チップとして登録**でき、次の回路の部品として置ける。
NOT を作り、それで AND を作り、それで加算器を作り……と階層を積み上げていくと、
最後は「記憶する回路」まで届く。

```
NAND ─→ NOT ─→ AND ─→ OR ─→ XOR ─→ 半加算器 ─→ 全加算器 ─→ 4ビット加算器
                        └─→ セレクタ            └─→ 2ビット乗算器
                              SR ラッチ ─→ D ラッチ ─→（ここから先は「ここから先」の節へ）
```

`回路ラボ.vbs` をダブルクリック（既定のブラウザで `index.html` が開く）。
`index.html` を直接開いてもよい。ビルドもインストールも要らない。

URL パラメータ:

| `?quest=xor` | 最初から選んでおく課題（id は下の表） |

## 最初の5分 ― NOT を作る

1. 左のパレットで **入力** をクリック → 盤面をクリック。スイッチ「A」が置かれる。
2. 同じように **NAND** と **出力**（「Y」）を置く。
3. 「A」の**右側の丸**から、NAND の**左側の丸（上）**へドラッグ。線が繋がる。
4. もう一度「A」の右の丸から、NAND の**左の丸（下）**へドラッグ。NAND の両方の入力に同じものを入れる。
5. NAND の右の丸から「Y」の左の丸へドラッグ。
6. 「A」をクリックして切り替えると、「Y」が逆に光る。**これが NOT**。
7. 右のパネルで課題「NOT」を選び、**採点する**。
8. 上の **チップにする** で `NOT` という名前を付けると、パレットに `NOT` が並ぶ。次から部品として置ける。

あとはこの繰り返し。

### 上のバー

- **止める / 動かす** ― 時間を凍らせる。止めている間はスイッチを動かしても値が広がらない。
  `Space` で1歩ずつ進めると、信号が波のように伝わっていく様子と、発振がどこで暴れているかが見える。
- **リセット** ― 全部を X（未定）に戻す。ラッチの記憶も消える。
- **真理値表** ― 今の回路の入力を全通り試して表にする。
- **論理式** ― 回路を式として読む。下の節を参照。
- **チップにする** ― 今の作業台の回路まるごとを名前つきの部品にする。
- **作業台を消す** ― 回路を空に。チップの定義は残る。
- **書き出し / 読み込み** ― JSON。人に渡すときはこれ。

## 課題

右のパネル。12問。組み合わせ回路は真理値表を総当りで、順序回路は入力を順に与えて採点する。

| # | id | 名前 | お手本の NAND 数 |
|---|---|---|---|
| 1 | `not` | NOT | 1 |
| 2 | `and` | AND | 2 |
| 3 | `or` | OR | 3 |
| 4 | `xor` | XOR | 4 |
| 5 | `mux` | 2:1 セレクタ | 4 |
| 6 | `half` | 半加算器 | 5 |
| 7 | `full` | 全加算器 | 13 |
| 8 | `dec24` | 2→4 デコーダ | 10 |
| 9 | `add4` | 4ビット加算器 | 52 |
| 10 | `mul2` | 2ビット乗算器 | 18 |
| 11 | `srlatch` | SR ラッチ | 2 |
| 12 | `dlatch` | D ラッチ | 5 |

「お手本の NAND 数」は `tests/quest.js` が実際に組んだ解答の実測値。

入力部品の名前も `A`・`B`、出力部品の名前も `Y` でなければならない。
右のパネルの端子タグは、その名前が今の回路にあると緑になる。

## 仕組み

依存の向きは上から下への一方通行。上の層は下の層を知らない。

```
netlist.js   回路のデータ構造（部品・配線・端子）。純粋なデータ操作だけ
   ↓
lib.js       チップの登録と、階層を潰して平らにする展開
   ↓
sim.js       3値・単位遅延・イベント駆動のシミュレータ
   ↓
truth.js     真理値表の抽出、ループの検出、期待表との突き合わせ
   ↓
quest.js     課題の定義と採点
expr.js      回路を論理式として読み、整理する
   ↓
store.js     localStorage への保存と JSON 入出力
   ↓
ui.js        canvas への描画と、マウス・キーボードの操作
   ↓
main.js      起動
```

`ui.js` 以外はブラウザに一切触らない。だから `tests/` は全部 Node だけで走る。

### 保存場所

ブラウザの `localStorage`（キー `NandLab.v1`）。ファイルには触らない。
他のマシンへ持っていくときは「書き出し」で JSON にする。

## 論理式で過程を見る

上のバーの **論理式**。回路を式として読み、2段で見せる。

**まとめ** ― 各出力の、最後まで整理した式。

```
S = A ⊕ B
Y = A · B
```

**過程** ― NAND を上流から順に1行ずつ。左が「回路のとおり」、右が「整理すると」。
式が育っていく様子がそのまま出る。

```
信号   回路のとおり      整理すると
s1     ¬(A · B)          ¬(A · B)
s2     ¬(A · s1)         ¬(A · s1)
s3     ¬(B · s1)         ¬(B · s1)
s4     ¬(s2 · s3)        A ⊕ B
s5     ¬(s1 · s1)        A · B
```

2箇所以上から使われる信号（上の `s1`）は、以降の式でその名前のまま出る。
全部を展開すると 4ビット加算器あたりで式が数千文字になって読めなくなるため。

### 整理に使っている書き換え

```
¬¬x            → x
x·x            → x                （同じものは1つにまとめる）
x·¬x           → 0,  x+¬x → 1
¬(¬a · ¬b)     → a + b            （ド・モルガン）
a·t + b·t      → (a+b)·t          （共通因子でくくる）
¬(a·b) · (a+b) → a ⊕ b
a·¬b + ¬a·b    → a ⊕ b
```

この程度の規則しか無いが、NAND で組んだ NOT・AND・OR・XOR・セレクタ・加算器は
これで人が書くのと同じ形まで戻る。XOR は「くくる」を先にやらないと気づけない
（`¬(a·b)·a + ¬(a·b)·b` → `¬(a·b)·(a+b)` → `a ⊕ b`）。

### ループがあると式にならない

順序回路の出力は「今の入力」だけでは決まらない。SR ラッチの Q は S と R の式では
書けない（同じ入力に対して答えが2つある）。無理に何かを出すより、
順序回路であることをはっきり言う。動きを見たいときは「止める」＋「1歩」で追う。

繋ぎ忘れた入力は `X` のまま式に出る（`Y = ¬(A · X)`）。0 で埋めたことにしない。

## 設計判断とその理由

### 原始部品は NAND だけ

AND も OR も XOR も、最初から用意されていない。それを作るのがこのアプリだから。
例外は「値を外から入れる/外へ出す」ための端子と、定数とクロックだけ。
これらは論理素子ではなく、回路と外界の境目。

### 信号は 3値（0 / 1 / X）

`X` は「まだ決まっていない」。**これが無いと嘘の回路が動いてしまう。**

0/1 だけだと、電源を入れた瞬間のフリップフロップが 0 から始まる。実物はどちらに
転ぶか分からない。X があると「リセットを入れるまで中身は読めない」という本当の挙動になり、
リセット線を忘れた回路はちゃんと動かない。繋ぎ忘れた入力も X になるので、
「繋ぎ忘れているのに偶然動いている」が起きない。

NAND の3値表で大事なのは、**片方が 0 なら、もう片方が未定でも出力は 1 で確定する**こと:

|        | b=0 | b=1 | b=X |
|--------|-----|-----|-----|
| **a=0**|  1  |  1  |  1  |
| **a=1**|  1  |  0  |  X  |
| **a=X**|  1  |  X  |  X  |

### 収束反復ではなく、単位遅延のイベント駆動

「出力が変わらなくなるまで全ゲートを計算し直す」方式は、**フィードバックのある回路
＝ラッチで原理的に破綻する**。SR ラッチは同じ入力に対して答えが2つある（Q=0 でも Q=1 でも
辻褄が合う）ので、不動点が一意に決まらない。

全ゲートに遅延 1 を与えて時間を1歩ずつ進めれば、ラッチは自然に「前の状態を保つ」ようになり、
禁止入力から抜けたときの発振も、発振としてそのまま観測できる。

1歩の中では**評価と反映を分ける**。1つずつ書き戻すと、評価する順番によって答えが変わり、
同じ回路が実行のたびに違う挙動になる。

### チップは展開してから回す

シミュレータは階層を知らない。回す前にチップを再帰的に潰して、
`nand` と `src`（値の源）と `buf`（中継）だけの平らな配列にする。

チップの境界は `buf` として残す。境界のネットを消して両側を直結する方が速いが、
そうすると「このチップのこの端子に今なにが来ているか」を画面に出せなくなる。
遅延が1段増えるだけなので残している。

ゲート i の出力ネットの番号は i と同じ。ネットとゲートを別々に採番すると、
対応表を持ち歩くことになる。

### 端子は必ず 10px 格子の上に載せる

端子の y が半端な値だと、部品の高さが違うだけで配線が斜めになり、
どう動かしても直線にできない（`46/3 = 15.33…` のような座標が出るため）。
そこで寸法を次の規則で決めている:

- 端子の間隔 `PITCH` は格子の偶数倍（20）
- 部品の高さは必ず 20 の倍数 → 中心 `h/2` は 10 の倍数
- 端子は中心から上下に対称 → ずれは `(端子数-1)×10` で 10 の倍数

よって端子の y は常に 10 の倍数。部品は格子に吸い付くので、
上下に動かせば任意の2端子をぴったり揃えられる。

### 端子の並び順は「名前の自然順」

座標順にすると、部品をちょっと動かしただけで端子の順番が入れ替わり、
そのチップを使っている側の配線が黙って繋ぎ変わる。名前なら動かない。

自然順なので `A1 < A2 < A10`。辞書順だと `A10` が `A2` より前に来て、
4ビット加算器の端子の並びが人間の直感とずれる。

### チップは「登録した時点のコピー」、参照は「名前」

作業台をいじるたびに登録済みチップの中身が変わると、何を測っているのか分からなくなる。
だから定義は登録時のスナップショット。

一方、盤面に置いたチップは**名前で**定義を引く。だから
**同じ名前で登録し直すと、そのチップを使っている回路すべてが新しい中身に入れ替わる**。
これは意図した挙動（バグを直したら全部に反映されてほしい）。
端子の数や名前が変わったときは、行き先を失った配線は展開時に黙って捨てられ、
`netlist.validate` が「存在しない端子を指しています」と指摘する。

## 踏みやすい落とし穴

- **チップの端子の順番は、作った順ではなく名前順。**
  SR ラッチを `S`・`R` の順で作っても、チップの入力は `R`・`S` の順に並ぶ。
  配列の添字で繋ぐと取り違える。`tests/quest.js` はこれを一度踏んで、
  名前で指定する `chipn()` を足した。

- **NAND を輪にしただけでは発振しない。** 全部が X のままでも3値の理屈は辻褄が合う
  （`NAND(X, X) = X`）。リング発振器を作るなら、既知の値を注ぐ口（起動用の入力）が要る。
  実物のリング発振器に必ず起動用のゲートが付いているのと同じ理由。

- **入力スイッチの初期値は 0。** SR ラッチのように「0 で効く」負論理の回路を組むと、
  電源投入直後がいきなり禁止入力になっている。課題の採点は `reset()` のあとに
  `settle()` せず、最初の手順の入力を与えてから初めて時間を進めることで
  これを避けている（settle してしまうと手順1で発振する）。

- **時間を止めているとき、スイッチを動かしても値は広がらない。** 仕様。
  `Space` で1歩ずつ進める。これを知らないと「壊れた」に見える。

- **`*.vbs` は UTF-16LE(BOM) で保存すること。** UTF-8 だと日本語の文字列リテラルが
  壊れて起動しない。先頭バイトが `FF FE` か確認する。`.gitattributes` で `binary` 指定済み。

## 検査

```
node tests/all.js       全部（250件）
node tests/run.js       エンジンの単体検査
node tests/expr.js      論理式が人の書く形まで戻ることの確認
node tests/quest.js     全課題のお手本解答を実際に組んで採点が通ることの確認
node tests/ui.js        画面の通し検査（ブラウザ不要）
```

全部 Node だけで走る。ブラウザは要らない。

- `tests/run.js` ― 部品と配線、3値 NAND、記憶と発振、ループ検出、チップの階層と循環検出。
- `tests/expr.js` ― NAND を積んだだけの回路が `A ⊕ B` や `A · ¬S + B · S` まで戻ること。
  ここが通らないと「論理式」ボタンは `¬(¬(A·B)·¬(A·B))` のような読めないものを出す。
- `tests/quest.js` ― NOT から D ラッチまでを実際に下から積み上げる。
  課題の期待表そのものの検算でもあり、チップ機構（階層・展開・境界をまたぐフィードバック）の
  総合試験でもある。わざと間違えた回路がちゃんと落ちることも見ている。
- `tests/ui.js` ― `tests/dom.js` の薄いニセ DOM の上で `ui.js` を動かし、
  人がやる手順（置く→繋ぐ→切り替える→採点→チップ化→中を覗く）をそのまま踏む。
  座標の計算には**画面の当たり判定と同じ関数**（`NL.ui.geom`）を使っている。
  別実装にすると検査が嘘になる。

**消さないでほしい検査:**

- `tests/run.js` の「電源投入直後は未定。0 から始まったりしない」
  ― X を消したくなったときの歯止め。
- `tests/quest.js` の「わざと間違えた回路は落ちる」
  ― 採点が素通りするようになったことに気づけなくなる。
- `tests/ui.js` の「盤面をちゃんと描いている（真っ白ではない）」
  ― 描画命令の数を数えている。例外を握り潰したときに気づける。

## ここから先 ― CPU までの道順

D ラッチまで来たら、残りは積み上げるだけ。ここから先は課題になっていないので自由制作。

1. **エッジトリガ D フリップフロップ**（D ラッチ2段の主従構成、NAND 11個ほど）
   クロックが「変化している間」ではなく「変わった瞬間」に取り込むようにする。
   これが無いと、レジスタの出力を自分の入力に戻したときに値が突き抜ける。
2. **4ビットレジスタ**（D-FF ×4、44個ほど）
3. **4ビット ALU**（加算器 + 入力反転で減算 + 論理演算 + セレクタ、120個ほど）
4. **プログラムカウンタ**（レジスタ + 加算器）

ここまでは手で配線できる範囲。**その先はメモリで詰まる。**
16語×4ビットの RAM を NAND で組むと 600素子を超え、手で配線するのは現実的でない。

つまり次の一手は、**RAM / ROM を組み込み部品として足すこと**。
NAND 純血ではなくなるが、そこは正直に「ここだけは実装部品」と割り切る類のもの。
足す場所は決まっている:

- `netlist.js` の `PRIM` に端子数を足す
- `lib.js` の `expand` に新しいゲート種別を足す
- `sim.js` の `evalGate` に評価を足す
- `ui.js` の `GEO` と `drawPart` に見た目を足す

シミュレータ側の余力はある（展開の上限は 200,000 素子、イベント駆動なので
大きい回路でも動いた所しか計算しない）。詰まるのは配線の手間の方。

その他、あると便利そうなもの:

- 順序回路の課題（今の採点機構は既に対応済み。`quest.js` に `kind: 'seq'` で足すだけ）
- 部分選択してチップにする（今は「作業台まるごと」だけ）
- 配線の自動整列
