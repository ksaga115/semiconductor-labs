# 画素ラボ

**中身の伏せられたカメラを撮って、測って、当てる。** そして自分の画素を設計して、仕様を満たす。

ブラウザだけで動く。依存ゼロ・通信ゼロ。
参考書 [イメージセンサ解剖ラボ](../第4部_イメージセンサ.html) が「画素の中で何が起きているか」を
説明する側なら、こちらは**自分の手で測って、答え合わせをする**側 ― あの資料には採点つきの課題が無いので、
そこだけを担う。参考書の各節の末尾に、対応する課題へ飛ぶ箱がある。量子効率と暗電流の温度依存は
[SemiLab](../SemiLab/) の物理をそのまま使う。全体の位置は [学びの地図](../index.html)（第4部）。

```
   工程        →    フォトダイオード    →    画素・カメラ
 ＝ProcessLab       ＝SemiLab（量子効率・ni）  ＝ここ（PixelLab）
```

## 起動

`起動.vbs` をダブルクリック。**SemiLab と同じフォルダ（`Labs\半導体\`）に兄弟として置くこと** ―
`../SemiLab/src/*.js` を読み込んでいる。

- `?fresh=1` … 保存を無視して最初から
- `?quest=k` … その課題を選んだ状態で開く（課題のカメラに切り替わる）
- `?sweep=1&fit=1` … 開いたらすぐ掃いて、当てはめの線も出す（画面の確認用）

検査: `node tests/all.js`

## 最初の5分

1. 上の「カメラ」で **謎のカメラ A** を選び、「**掃く**」。露光を 0.1ms〜5s で 40 通りに変えて、
   明るい2枚・暗い2枚ずつ撮る。
2. 右上の **PTC**（両対数）を見る。左の平らな所が読み出し雑音、右肩上がりの坂（傾き 1/2）がショットノイズ、
   頂点が飽和。
3. 左下の図（分散 − 暗い分散 と 平均）が直線になっている範囲の**傾きの逆数が K**。
   右の課題「変換係数 K を当てる」に数を入れて採点。
4. わからなければ「当てはめを見せる」を付ける。白い破線が自動の当てはめ。
5. カメラを「設計したカメラ」に戻して、浮遊拡散の容量を 2 → 1.3 fF に変える。読み出し雑音が下がり、
   ダイナミックレンジが上がる。0.5 にすると「飽和電荷を決めたのは 浮遊拡散」に変わって井戸が縮む。

## 仕組み

```
rng.js      種を決めた乱数（mulberry32）。ポアソン（光子・暗電流）と正規（読み出し）
pixel.js    設計 → カメラの数字（量子効率は SemiLab、暗電流の温度は ni(T)）
camera.js   平らな光を撮って1枚の画像を返す。謎のカメラ A/B/C の真の値もここ
ptc.js      明るい2枚・暗い2枚から1点を測る（差分法）。K・読み出し・飽和・暗電流・PRNU の当てはめ
quest.js / answer.js / store.js / ui.js / main.js
```

### 1画素に起きること（camera.js）

1. 光子が来て電子になる ― ポアソン（平均 = 量子効率 × 光子束 × 面積 × 露光 × その画素の感度）
2. 暗電流の電子も溜まる ― ポアソン
3. 井戸があふれたら頭打ち
4. 電子 ÷ K ＋ 読み出し雑音（正規）＋ オフセット
5. AD で整数にして 0〜2^bits−1 に収める

画素ごとの感度のむら（PRNU）と暗電流のむら（DSNU）はカメラごとに1回だけ振って覚えておく（固定パターン）。

### PTC の差分法（ptc.js）

電子で数えれば「分散 ＝ 平均」（ポアソン）。DN で測ると `分散[DN²] = 平均[DN]/K + 読出²[DN²]` なので、
**傾きが 1/K**。1枚の分散には固定パターンが混ざって傾きが歪むので、**同じ条件で2枚撮って差を取る**
（差の分散 ÷ 2 が時間でゆらぐ分散）。平均からは同じ露光の暗い画像の平均を引く（オフセットと暗電流が消える）。

### 設計（pixel.js）

| 出てくる数字 | 式 |
|---|---|
| 画素の量子効率 | SemiLab の量子効率 × （マイクロレンズがあれば 0.9、無ければ PD の割合） |
| 飽和電荷 | min(井戸の深さ × PD の面積, 浮遊拡散の容量 × 1V / q) |
| 変換ゲイン | q / C_FD |
| 読み出し雑音 | 回路の雑音 ÷ 変換ゲイン（CDS が無ければ √(kTC)/q も足す） |
| K | 飽和電荷を AD の上限の 95% に割り当てる |
| 量子化雑音 | K / √12 |
| 暗電流 | 暗電流密度（60℃）× PD の面積 × ni(T)/ni(60℃) |
| ダイナミックレンジ | 20 log(飽和電荷 / √(読出² + 量子化²)) |
| 1 行の時間 | 2^bits / クロック ÷ 同時に読む行（単一傾斜の AD の変換時間が 1 行を決めると仮定） |
| ローリングの横ずれ | 物体の速さ × 行数 × 1 行の時間（第4部: 3000 行を 1/60 秒なら 1 行 5.6 µs・上下 16.7 ms） |
| 寄生の偽の信号 | 量子効率 × 光子束 × 面積 × 10^(−dB/20) × 読み出しの全時間（最後の行が一番長く待つ） |
| 回折の限界の画素ピッチ | λN/2（遮断周波数 1/(λN) ＝ ナイキスト 1/(2p)）。エアリー円板 2.44λN |
| TDI の S/N | N·S₁ / √(N·S₁ + σ²)（電荷で足す）、N·S₁ / √(N·S₁ + N·σ²)（デジタルで足す）。にじみ ＝ N × ずれ |
| つなぎ目の SN 比 | 長い側 fw/√(fw + 床²)、短い側 (fw/R)/√(fw/R + 床²)（長い露光が飽和の直前で切り替わる） |
| 暗電流の欠陥の成分 | 欠陥の暗電流密度（60℃）× PD の面積 × exp(−E_a/k·(1/T − 1/T₆₀))、E_a 0.35 eV（仮定・第4部 付録C）。生成の成分に足す |
| SPAD | 数えられる率 r/(1 + rτ_d)（不感時間の間は無視する型）、距離のばらつき c·σ_t/2/√N |

## どこまでが本当で、どこからがモデルか

- **本当に振っている**: 光子と暗電流のショットノイズ、読み出し雑音、量子化、井戸と AD の飽和、固定パターン
- **SemiLab で解いている**: 量子効率（p+ 0.15µm / n 1e15 エピ / n+ のフォトダイオードを逆バイアス 2V で）、
  暗電流の温度依存（ni(T) に比例 ― 空乏層の生成電流）。**「約 9℃（300 K 付近で 8.6 K）で倍」は決め打ちではなく ni から出てくる**
- **まとめてある**: 読み出し回路の雑音（ソースフォロワの熱雑音・1/f・列回路を1つの µV にしてある）、
  井戸の深さ（1µm² あたりの電子の数）、浮遊拡散の電圧の振れ幅（1V）
- **第4章・第5章は式だけ**: ローリングシャッタの歪み・寄生感度・回折の限界・TDI は、撮影（camera.js）には入れず、
  設計の数字として式で出している。1 行の時間は単一傾斜の AD の変換時間 2^bits/クロックで決まると仮定した
  （実際は露光の制御・列の整定・ランプの繰り返しなどの時間も乗り、AD の方式もいろいろある）。
  寄生感度は分離比 1 つにまとめ、波長や入射角による違いは入れていない。回折は単色・無収差のレンズの上限。
  TDI は物体の速さのずれが一定、段ごとの暗電流は無視している
- **入れていないもの**: 転送の残り（ラグ）、ランダム・テレグラフ雑音（RTS）、白キズ、クロストーク・カラーフィルタ、
  HDR の二重変換ゲイン。どれもイメージセンサ解剖ラボが説明しているので、こちらでは扱わない

## 繰り返し踏んだ落とし穴

### 1. 井戸を測ったつもりで、AD の上限を測っていた

最初、謎のカメラ A を 12 bit にしていた。A の飽和電荷を K で割ると 7806 DN で、12 bit の上限 4095 を超える。
**井戸があふれる前に AD が振り切れ**、PTC の頂点は井戸ではなく AD の上限を示していた（飽和電荷が 57% 小さく出た）。
→ A は 14 bit にした。C はわざとこのままにして、「**飽和を決めているのはどちらか**」を当てる課題にした。
`tests/run.js` が「A と B は井戸が先、C は AD が先」という課題の前提を見張っている。

### 2. 1枚の分散では K が歪む

画素ごとの感度のむら（PRNU）は信号に比例して大きくなるので、1枚の分散で当てはめると傾きが大きく出て
K が小さく出る（`tests/run.js` がこの失敗の再現も確かめている）。**差分法が要る理由**。

### そのほか（SemiLab・ProcessLab から持ち込んだ約束）

- 設計の欄は数値欄と選択肢だけ（摘みは使わない ― SemiLab で「動かしている最中に摘みが消える」を踏んだ）
- 読めない値は赤くして何も変えない。数値の読み取りは SemiLab の `parse.js`
- `Math.random` を使わない（種を決められないと、測った値が合っているかを機械が確かめられない）。検査が見張っている
- 見た目の崩れは Node の検査では落ちない。1280px と 1024px で撮って確かめる
- 検査の道具は SemiLab の `tests/check.js`・`tests/dom.js` を共用

## ここから先

- **HDR** … 二重変換ゲイン（明るいときだけ浮遊拡散に容量を足す）で、ダイナミックレンジの壁を越える
- **光学** … F 値と光子束をつなぐ（いまは画素に届く光子束を直接与えている。F 値は第4章の回折の限界だけに使っている）
- **撮影にも動きを入れる** … ローリングシャッタの歪みと寄生感度を、式だけでなく撮った画像に出す
- **ProcessLab からフォトダイオードを受け取る** … 工程で作った接合で量子効率を出す
